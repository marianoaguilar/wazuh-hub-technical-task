## Summary
EPSS gives every published CVE a daily probability (0 to 1, plus a percentile) that exploitation activity will be observed in the next 30 days. FIRST publishes it free of charge, with no registration, as a daily CSV file and through a REST API (marked BETA). The pages read do not name a formal license; the FAQ asks for attribution when EPSS is used in publications or products. FIRST's own guidance says KEV-listed CVEs should be treated as exploited regardless of EPSS, and EPSS must not be multiplied by CVSS.

## Claims
1. EPSS estimates the probability that a published CVE will be exploited in the wild in the next 30 days, as a 0-1 score with a ranking percentile, every day for every CVE.
   - Quote: "estimates the probability that a published CVE will be exploited in the wild in the next 30 days." / "publishes a 0–1 probability (with ranking percentiles) every day for every CVE"
   - Source: https://www.first.org/epss/
   - Confidence: high

2. The FAQ defines the score more precisely as the likelihood that a data partner observes exploitation activity in 30 days, and says it is not a complete risk score (no impact or environmental context).
   - Quote: "is an estimate of the likelihood that any one of our data partners" [will detect exploitation activity within the next 30 days]; "is not a complete risk score"
   - Source: https://www.first.org/epss/faq
   - Confidence: high

3. Update frequency: new scores are published daily, typically shortly after 13:30 UTC; model retraining is not on a fixed calendar.
   - Quote: "Daily. New scores are published each day covering every scored vulnerability" / "within a minute or two after 13:30 UTC daily."
   - Source: https://www.first.org/epss/faq
   - Confidence: high

4. Bulk download: a stable URL always returns the current day's full CSV (gzip), and it redirects (curl needs `-L`): `https://epss.empiricalsecurity.com/epss_scores-current.csv.gz`.
   - Quote: "The URL does not change; fetching it always returns today's scores."
   - Source: https://www.first.org/epss/data
   - Confidence: high

5. The API should not be used for bulk sync; the daily CSV or GitHub repo is the intended mechanism for keeping a local copy.
   - Quote: The API "should not be used for bulk downloads or to keep a local copy of all scores in sync; the daily CSV or the GitHub repository is the right mechanism for that."
   - Source: https://www.first.org/epss/data
   - Confidence: high

6. API: base URL `https://api.first.org/data/v1/epss`, marked BETA; accepts `cve` (comma-separated, max 2000 characters), `date` (YYYY-MM-DD, data since 2021-04-14), score/percentile filters, and a `time-series` scope with the last 30 days. Each result has cve, epss, percentile, date.
   - Quote: "https://api.first.org/data/v1/epss" / "The maximum size accepted for this parameter is 2000 characters (including commas)."
   - Source: https://api.first.org/epss
   - Confidence: high

7. Scores are generated by Empirical Security and EPSS is maintained by the EPSS SIG at FIRST; there is also a GitHub repository of scores (github.com/empiricalsec/epss_scores, linked from the EPSS home page).
   - Quote: "Scores are generated by Empirical Security and published freely to the community."
   - Source: https://www.first.org/epss/using-epss ; https://www.first.org/epss/
   - Confidence: high

8. Terms of use: access is free and needs no registration; attribution is requested when EPSS data is used in publications or products. No specific license is named on the pages read, and the API page shows only a general FIRST copyright notice.
   - Quote: "published freely via CSV download and API with no registration required." / "Attribution is requested when EPSS data is used in publications or products."
   - Source: https://www.first.org/epss/faq
   - Confidence: medium (official, but no formal license text was found)

9. FIRST guidance on combining signals: treat a KEV-listed CVE as actively exploited regardless of EPSS; do not multiply EPSS by CVSS.
   - Quote: "treat it as actively exploited and prioritize accordingly, regardless of EPSS score." / "Do not multiply an EPSS score by an ordinal (such as CVSS) and think that produces a combined" [risk score]
   - Source: https://www.first.org/epss/using-epss
   - Confidence: high

10. FIRST gives rough thresholds for teams moving from CVSS: about the 90th percentile (EPSS >= 0.04) matches the population size of a CVSS Critical filter, and about 0.008 matches CVSS High and above, as a starting point only.
    - Quote: "a starting point for programs migrating from a CVSS-anchored workflow"
    - Source: https://www.first.org/epss/using-epss
    - Confidence: high

## Inference
- Inference: For a SaaS, the right pattern is one daily CSV download after ~13:30 UTC into a local table, not per-finding API calls. Show "EPSS data from FIRST" attribution in the UI.
- Inference: A ranking can use KEV as an override tier (always first), then EPSS percentile, and use CVSS/asset context as separate dimensions instead of multiplying them.
